## What is generated

| generated | from | rebuilt by | checked by |
|---|---|---|---|
| `crates/conductor-model/` | the specification in `spec/` | `task regen` (`ess generate synthesize --path spec --target rust --layout crate`) | `task check`: a fresh generation into `.check/conductor-model`, compared with `diff -r` |
| `crates/conductor/dashboard/dist/` | the dashboard app in `crates/conductor/dashboard/src/` | `task ui` (`npm ci`, then `npm run build`) | `task check`: `task ui`, then `git diff --exit-code` and no untracked file under `dist/` |
| `website/docs/reference/cli.md` | the clap definition of `conductor` | `task docs-generate` | `task docs-check` |
| `website/docs/reference/config.md` | `spec/domains/config.yaml` and the defaults `conductor` fills | `task docs-generate` | `task docs-check` |
| `website/docs/reference/crates.md` | `cargo metadata --no-deps` | `task docs-generate` | `task docs-check` |
| `website/docs/status.md`, `website/data/status.json` | the capability list `CAPABILITIES` in `crates/conductor-docs/src/status.rs` | `task docs-generate` | `task docs-check` |

Do not edit any of these by hand. Each generated page starts with the front-matter line and the
comment "generated by conductor-docs, do not edit". To change one, change its source and
regenerate:

| change | then |
|---|---|
| `spec/` | `ess specify validate --path spec`, then `task regen`, then build against the new types. `task regen` removes `crates/conductor-model` and writes it again, so a hand edit there is lost |
| a command, flag or config field | `task docs-generate`, and commit the changed reference pages with the code |
| a capability shipped or planned | edit `CAPABILITIES` in `crates/conductor-docs/src/status.rs`, then `task docs-generate`. A shipped capability names its test as `path::function`, and generation fails when that file does not define the function |
| the dashboard app | `task ui`, and commit `dist/` with the change |

`task docs-generate` runs `cargo run --locked -p conductor-docs -- generate`. It replaces the whole
of `website/docs/reference/`, so a file added there by hand is removed.

## Rebuild the dashboard app

The app is Vue 3, Vite and TypeScript, on the Node version in `crates/conductor/dashboard/.nvmrc`,
with the packages its `package-lock.json` locks. The binary embeds `dist/` when it is compiled, so
building or installing conductor needs no Node. Developing conductor does, because `task check`
rebuilds the app.

```console
task ui        # npm ci, then vue-tsc --noEmit and vite build into crates/conductor/dashboard/dist/
task ui:dev    # the app from source with hot reload on http://127.0.0.1:5173/
```

`task ui:dev` sends its `/v1/` requests to the running daemon, `CONDUCTOR_DAEMON` or
`http://127.0.0.1:7300`, so start conductord first. `npm test` in `crates/conductor/dashboard` runs
the Vitest suite against the fixture `src/fixtures/data.json`.

## What docs-check checks

`task docs-check` runs `conductor-docs generate --check`. It writes nothing and exits 1 with one
line for each:

- generated file that is missing, or differs from a fresh generation ("stale or edited");
- file under `website/docs/reference/` the generator does not write ("not generated");
- place a Markdown page under `website/docs/` is not passive Markdown, hand-written pages
  included, as `<page>:<line>: <problem>`.

It is the last step of `task check`.

## The passive-Markdown rule

The site's pages are collected by a shared documentation site that refuses executable MDX, so
every page under `website/docs/` is plain Markdown. Outside fenced blocks and inline code spans, a
page may not hold:

| not allowed | because | write instead |
|---|---|---|
| a `{` | MDX reads it as the start of an expression | `\{`, or put it in code |
| a line starting with `import` or `export` | MDX reads it as a module statement | put it in code |
| a tag starting with a capital letter, such as `<Value>` | MDX reads it as a component | put it in code |
| an admonition title without brackets, such as `:::tip Title` | Docusaurus prints it as raw text | `:::tip[Title]` |

A code fence that is not closed is a problem too. Front matter is not checked. The rule is
`crates/conductor-docs/src/pages.rs`, and its unit tests show each case.

## Preview the site

The site is Docusaurus. Install its dependencies once, then serve it with live reload:

```console
npm --prefix website ci
npm --prefix website start
```

To build it the way CI does:

```console
npm --prefix website ci && npm --prefix website run build
```

The build fails on a broken link or anchor. `.github/workflows/pages.yml` runs that build on every
push to `main`, on every pull request and on `workflow_dispatch`. It then runs
`cargo test -p conductor-docs` and binds the built site to its commit with
`conductor-docs provenance`, which writes `.well-known/b10x-routes.json`.

:::tip[Before you push a page]
Run `task docs-check`. It reports a stray `{` or an unbracketed admonition title by page and line,
which the site build reports less plainly.
:::
