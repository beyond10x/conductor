## Why

Conductor's public documentation needs reference pages that cannot drift from the code: the CLI
reference from the clap definitions, the config reference from the specification, the crate list,
and the status page. The ecosystem's sites generate these from a `<repo>-docs` crate whose
`generate --check` runs in the gate (the shape of `loom-docs`).

## Acceptance

- A workspace crate `crates/conductor-docs` (package `conductor-docs`, `publish = false`) with a
  binary of the same name and the commands:
  - `generate`: writes `website/docs/reference/cli.md` (every command and leaf with its arguments,
    from `conductor_cli::cli::Cli` through clap), `website/docs/reference/config.md` (every config
    key with type, default and rule, from `spec/domains/config.yaml` and the defaults in
    `conductor_cli::config`), `website/docs/reference/crates.md` (from `cargo metadata`), and
    `website/data/status.json` (`format: b10x-status/1`) plus `website/docs/status.md`; each
    generated page starts with `<!-- generated by conductor-docs, do not edit -->` style front
    matter comment and `custom_edit_url: null`.
  - `generate --check`: exits 1 and names the file when any generated file differs.
  - `provenance --site <dir> --commit <sha>`: writes the provenance file and
    `.well-known/b10x-routes.json` into a built site, as `loom-docs` does.
- The status capability list lives in the crate; every `shipped` item names the test that holds it
  as `path::function`, and `generate` refuses a name that does not exist.
- `Taskfile.yml` gains `docs-generate` and `docs-check`, and `check` runs `docs-check`.
- No story ids, no organization names in any generated text; package descriptions are public.

## Scope

`crates/conductor-docs/**` (new), `Cargo.toml` workspace members, `Cargo.lock`,
`Taskfile.yml` tasks `docs-generate`, `docs-check`, `check` (cited), `website/docs/reference/**`,
`website/data/status.json`, `website/docs/status.md` (generated output).
