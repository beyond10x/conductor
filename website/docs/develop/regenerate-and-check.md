## What is generated

| generated | from | rebuilt by | held by |
|---|---|---|---|
| `crates/conductor-model/` | the specification in `spec/` | `task regen` (`ess generate synthesize --path spec --target rust --layout crate`) | `task check`: a fresh generation into `.check/conductor-model`, compared with `diff -r` |
| `website/docs/reference/cli.md` | the clap definition of `conductor` | `task docs-generate` | `task docs-check` |
| `website/docs/reference/config.md` | `spec/domains/config.yaml` and the defaults `conductor` fills | `task docs-generate` | `task docs-check` |
| `website/docs/reference/crates.md` | `cargo metadata --no-deps` | `task docs-generate` | `task docs-check` |
| `website/docs/status.md`, `website/data/status.json` | the capability list `CAPABILITIES` in `crates/conductor-docs/src/status.rs` | `task docs-generate` | `task docs-check` |

Never edit any of these by hand. Each generated page starts with a front-matter line and a comment
saying "generated by conductor-docs, do not edit". To change one, change its source and
regenerate:

- **A change to `spec/`.** Run `ess specify validate --path spec`, then `task regen`, then build
  against the new types. `task regen` removes `crates/conductor-model` and writes it again from
  scratch, so a hand edit there is lost and a stale file cannot survive.
- **A new or changed command, flag or config field.** Run `task docs-generate` and commit the
  changed reference pages with the code.
- **A capability that shipped or was planned.** Edit `CAPABILITIES` in
  `crates/conductor-docs/src/status.rs`, then `task docs-generate`. A shipped capability names the
  test that holds it as `path::function`; generation fails if that file does not define the
  function, so a claim on the status page cannot outlive its test.

`task docs-generate` runs `cargo run --locked -p conductor-docs -- generate`. It replaces the whole
of `website/docs/reference/`, so a file you add there by hand is removed.

## What docs-check checks

`task docs-check` runs `conductor-docs generate --check`. It writes nothing and exits 1 naming:

- each generated file that is missing, or differs from a fresh generation ("stale or edited");
- each file under `website/docs/reference/` the generator does not write ("not generated");
- each place a Markdown page under `website/docs/` is not passive Markdown, hand-written pages
  included, as `<page>:<line>: <problem>`.

It is the last step of `task check`.

## The passive-Markdown rule

The site's pages are collected by a shared documentation site that refuses executable MDX. So
every page under `website/docs/` must be plain Markdown. Outside code (fenced blocks and inline
code spans), a page may not hold:

| not allowed | because | write instead |
|---|---|---|
| a `{` | MDX reads it as the start of an expression | `\{`, or put it in code |
| a line starting with `import` or `export` | MDX reads it as a module statement | put it in code |
| a tag starting with a capital letter, such as `<Value>` | MDX reads it as a component | put it in code |
| an admonition title without brackets, such as `:::tip Title` | Docusaurus prints it as raw text | `:::tip[Title]` |

A code fence that is never closed is a problem too. Front matter is not checked. The rule is
`crates/conductor-docs/src/pages.rs`; its unit tests show each case.

## Preview the site

The site is Docusaurus. Install its dependencies once, then serve it with live reload:

```console
npm --prefix website ci
npm --prefix website start
```

To build it the way CI does:

```console
npm --prefix website ci && npm --prefix website run build
```

The build fails on a broken link or anchor. `.github/workflows/pages.yml` runs that build on every
push and pull request, then binds the built site to its commit with `conductor-docs provenance`.

:::tip[Before you push a page]
Run `task docs-check`. It names a stray `{` or an unbracketed admonition title by page and line,
which the site build reports less plainly.
:::
